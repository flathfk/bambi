## 4. 신규 발견 (심각도순)

### 🔴 High — 이번 주 처리

**H-1. `/assistant` UI가 무인증 + 기본 활성 + LLM 실행** — bambi-agent-api
`app/config.py:24-27` `enable_assistant_ui` 기본 True, `.env.example`에 항목 자체가 없어 배포자가 끌 수 없다. `app/assistant/web.py:488-492` `POST /assistant/search`가 인증 없이 임의 `user_id`로 수집+LLM 파이프라인을 실행한다. `include_in_schema=False`는 Swagger에서 감출 뿐 접근은 가능. **내부 API를 Bearer로 잠근 성과(1-4)가 같은 프로세스의 이 경로 하나로 상쇄된다** — 외부인이 OpenAI 비용을 무제한 유발 가능. H-3(공인 8000 포트 개방)과 결합 시 실제 노출 상태다. `docs/assistant-ui-removal.md`가 이미 제거 대상으로 지정 → 제거 전까지 기본값 False 전환이 최소 조치.

**H-2. 배포 시 워커 stop 목록이 낡아 시드 중 데이터 경합** — bambi-build
`deploy.yml:82` `docker compose stop agent-api agent-worker-wiki agent-worker-report` — 08-04 추가된 `agent-worker-url`(5초 간격)·`agent-worker-global-content`가 빠져 있다. stop의 목적("이전 워커가 Seed 변경 중 데이터를 처리하지 않도록", `deploy.yml:81` 주석)이 무너진 상태로, migration/seed가 도는 동안 두 워커가 agent-db에 계속 쓴다. 한 줄 수정.

**H-3. agent-api(8000)·agent-db(5432)가 공인 IP에 개방, Swagger 포함** — bambi-build
`docker-compose.yml:110-111,167-168`. 주석 스스로 "08-11 code freeze 전 제거"를 못 박았고 그 기한이 1주일 남았다. `DOCS_ENABLED` 기본 true(`:144`)라 Swagger UI로 내부 API 스키마 전체가 공개 중. compose 상단 주석(`:14`)은 여전히 "80이 유일한 노출 포트"라고 주장한다. GCP 방화벽 규칙 `allow-dev-agent-0727`도 함께 삭제 대상.

**H-4. AI 로그 평문 삽입 → 503이 500으로 둔갑 + 장애 기록 유실** — bambi-service-api
§3의 3-2와 동일 항목 (신규 원인 규명이라 여기에도 등재). agent가 죽었을 때 정확히 필요한 관측성이 정확히 그 순간 무너진다. 조치: `logResponse`에 넣기 전 문자열을 JSON 래핑(`{"error": "..."}`)하거나 로거 내부에서 방어.

**H-5. 웹 클리퍼가 비밀번호·JWT를 평문 HTTP로 전송** — bambi-clipper

## 7. 잘 된 것들

추적 리뷰의 공정성을 위해 명시한다. 아래는 07-26 대비 실질적 개선이다.

- **비동기 발행 경로가 실제로 관통됐다.** 생성 스케줄러(멱등키·per-user 격리) → 202 Job → claim/ack 실 HTTP → 항목별 트랜잭션 upsert → 부분 성공 ACK, 잘못된 페이로드는 영구 실패 분류로 무한 재시도 방지까지. 07-27 "(C) 결정"이 문서로 끝나지 않고 코드가 됐다.
- **agent 내부 인증의 구현 품질.** 라우터 레벨 일괄 적용 + fail-closed + 상수시간 비교 + OpenAPI 전수 회귀 테스트 — 신규 엔드포인트가 인증을 빼먹으면 CI가 깨지는 구조를 만들었다.
- **LLM이 mock이 아니라 실연동 + 벤치마크 문화.** critic 인용 검증 96.7%, 조사원 수집 판단을 프롬프트에서 코드로 옮겨 80%→100% 등 측정 후 개선의 흔적이 커밋 로그에 남아 있다. agent-api 테스트 734개 전부 통과.
- **service-web의 불변식 준수는 모범적.** 원시 fetch 1곳(공통 client), Agent 직접 호출 0건, `any` 0건, 시크릿 0건, mock/실 경계가 repository seam으로 격리, 데스크톱/모바일 내비가 단일 배열 공유.
- **시크릿 위생 기반기.** 전 레포 gitleaks(히스토리 전체) + `.env` 커밋 이력 0건 + clipper의 최소 권한(activeTab) 설계.
- **계약 깨짐을 막는 테스트의 방향성.** "누가 @JsonProperty를 지우면 이 테스트가 먼저 깨진다"는 주석이 보여주는 의도 — 교차 검증(P1-7)까지 가면 완성된다.
